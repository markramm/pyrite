- **Writes are checked against the KB they change, not only the caller's global role.** `POST /api/clip` now requires write access on the target KB, and `DELETE /api/reviews/{id}` checks write access on the review's own KB. A KB the caller cannot read answers 404, the same as one that does not exist; a KB they can read but not write answers 403. Starred entries are now per user (schema migration v24; existing stars become the instance's own list, which is what auth-disabled and operator-key callers see), and starring an entry in a KB the caller cannot read answers 404. `requires_kb_tier` on a route that names no KB is now a test failure.
