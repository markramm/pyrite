- **Bulk create refuses invalid items instead of writing them.** `kb_bulk_create`, `pyrite import` and task decomposition now refuse, per item, an entry whose id already exists (it used to be overwritten while reporting `created: true`, #359) and an entry the KB schema or a plugin validator rejects (#366), with the message `kb_create` gives. Siblings are still created, in order. Callers that sent off-schema values or reused titles will now see per-item errors.
- **`pyrite links bulk-create` edits an entry where it lives.** It used to re-derive the source entry's path from its type and write a second copy of any entry kept elsewhere (#375).
