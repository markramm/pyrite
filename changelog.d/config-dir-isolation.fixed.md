- **`PYRITE_CONFIG_DIR` now moves the index, and a registry is never emptied by accident** (#377). With no explicit `index_path`, the index (and cloned repos) default to the directory holding `config.yaml`, so `PYRITE_CONFIG_DIR=/tmp/x pyrite kb add ...` no longer registers into `~/.pyrite/index.db`; a default `~/.pyrite` install sees no change, and `PYRITE_DATA_DIR` and `settings.index_path` still take precedence (order in `docs/configuration.md`). `save_config` refuses to replace a `config.yaml` that lists knowledge bases with one that lists none unless the caller just removed exactly those KBs or passes `allow_empty=True`; a write through a symlinked `config.yaml` logs the real path. The test suite now exports `PYRITE_CONFIG_DIR`/`PYRITE_DATA_DIR` for the whole session, so `pyrite` subprocesses spawned by tests can no longer read or write the developer's `~/.pyrite`.
