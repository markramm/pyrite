- **`sw new-adr` goes through the write pipeline, and `file_pattern` gains entry-field placeholders (#391).** `sw new-adr` used to write the ADR file directly, bypassing `KBService`: an existing ADR number or id was silently overwritten, no validators or before/after-save hooks ran, the new ADR wasn't indexed until a separate `pyrite index sync`, and a KB that failed to resolve silently fell back to writing `./adrs` under the current directory. It now creates through `KBService.create_entry`: an existing id is refused with `ENTRY_EXISTS`, and no KB resolved refuses with `KB_NOT_FOUND` instead of writing anywhere. `TypeSchema.resolve_filename` (`file_pattern`) now supports the entry's own fields as placeholders, with an optional Python format spec (e.g. `{adr_number:04d}`), alongside the existing `{id}`/`{slug}`/`{date}`/`{title}`/`{type}`; a placeholder naming a field the entry doesn't have, or a value that would escape the type's folder (a path separator or `..`), is refused. The software-kb `adr` type declares `file_pattern: "{adr_number:04d}-{title}.md"` so new ADRs keep their existing `NNNN-slug.md` filename and `adr-NNNN` id.
