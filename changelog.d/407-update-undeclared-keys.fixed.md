- **`pyrite update -f key=value` no longer silently drops an undeclared key (#407).** A key that was neither a model attribute nor named in the KB's schema — `foo` on a note, `parked_awaiting`/`park_until` on a task — used to be dropped without warning: the command reported `{"updated": true}` and exited 0, but wrote nothing. `update` now stores the key wherever `create` would have (metadata, or a top-level frontmatter key), through the same schema validation. REST `PATCH /api/entries/{id}` with `field: foo` now stores it too.
