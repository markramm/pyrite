- **A kb.yaml-only type keeps every field it was given on create.** `build_entry` used to construct a type with no Python model class (declared only in `kb.yaml`) from just `tags`, `summary` and `metadata`, silently dropping any other field passed to `pyrite create -f`, MCP `kb_create`, or bulk/import (#386). Those fields now round-trip through `metadata`, the same as they already did for `pyrite add` and the indexer. One consequence for callers who were silently succeeding: a select/enum field on such a type is now visible to schema validation, so a KB with `validation.enforce: true` refuses an off-enum value it previously wrote anyway.
